# AtomUI 及生态项目的代码注释检查与补齐

## 何时使用

在 AtomUI 框架或生态项目中处理「检查注释」「补齐注释」「按规范修正注释」或「提交前检查注释」时使用。公开声明写使用契约，内部实现写维护时必须知道的原因与约束。

## 何时不使用

用户文档、发布说明、代码行为修改和 Git 提交按目标仓库对应的流程处理。含代码变动的提交按目标仓库要求执行注释审查。

## 确定范围与版本

1. 依据用户指定范围定位文件、控件、模块或变更集。普通检查未指定范围时，从本次代码变动及受影响的注释开始。读取相关声明和使用处以核实事实，修订限于用户要求的范围。
2. 从目标仓库的 `AGENTS.md` 或工程文档发现采用的注释规范。使用目标范围的明文规则。查阅随 Skill 附带的 [AtomUI 生态注释书写规范 1.0](references/atomui-code-comment-guidelines.md) 中和本次对象相关的详细规则及示例。只有正文可用时，使用下文的基线。
3. 「检查」保持只读。「补齐」或「修正」授权编辑注释内容。提交前检查用 `git diff --cached` 确定改动，并用 `git show :<path>` 等方式读取审查所需的暂存源码。涉及行为对比时参照基线源码。检查对象包括本次新增或修改的注释，以及本次声明或行为变化影响的注释。

## 核实契约并检查

沿实际声明、调用处、模板、生成规则或相关测试确认契约。检查覆盖、准确性、精简程度和排版。源证据不足时记录待核实的条目，继续处理有足够证据的项。

| 对象 | 检查内容 |
| --- | --- |
| 公开类型、成员、枚举值和外部派生扩展点 | 必须有英文 `<summary>` 或可解析的 `<inheritdoc />`。承担跨模块契约的内部成员也应有 XML 注释，内部注释默认使用英文。类型说明放在 `partial` 主声明上。重写和接口实现完整沿用原契约时使用继承注释。存在行为、限制或副作用差异时在当前声明写清。 |
| 行为契约 | 补足影响调用的单位、范围、特殊值、线程、顺序和副作用。布尔属性写清 `true` 的含义。`Try*` 写清成功与失败条件，以及两条路径的 `out` 值。异步方法说明任务完成和取消对状态的含义。事件说明触发原因、是否在提交状态前触发及取消阻止的动作。可重写成员说明调用时机、`base` 要求和生命周期约束。 |
| 控件公开样式属性 | 逐项核对设置位置、影响区域、生效条件、特殊值、覆盖和主题回退。有 CLR 包装时在包装属性写完整契约，公开注册字段简短指向该属性。无包装时由注册字段承担完整说明。附加属性核对值承载元素、读取方和传播范围。派生控件改变契约时说明差异。 |
| 手写 Token 与设计语言 | 每个 Token 写清影响哪里、改变什么、何时生效。全局 Seed、Map、Alias 各自说明设计角色和消费语义。控件 Own Token 区分区域、状态、尺寸档和模式。设计语言专属或保留中的 Token 写明具体作用或保留条件。每种设计语言的入口和关键取值规则说明输入、求值、叠加、冻结和回退中影响结果的部分。 |
| Semantic Part | 每条 `[SemanticPart]` 上方写清用户可识别的区域、何时存在及生成的公开专用 Style。适用时说明重复单位、状态替换或跨视觉根对命中的影响。复杂 `SelectorRoute` 的维护注释解释跨越宿主、模板或视觉根的原因。 |
| 实现、AXAML、测试和脚本 | 注释贴近受约束代码。写清顺序、兼容边界、资源所有权、替换和释放时机。有代码主题绑定时解释 `ControlTheme` 无法等价表达的原因。测试说明关键输入、步骤或断言为何必要，脚本说明隐含前置条件和副作用。临时处理、`TODO` 和 `FIXME` 写明剩余事项和移除条件。生成代码的注释在生成器、模板或源声明中维护。 |

### 内容与格式

- 摘要通常一句，优先写影响使用的事实。每项契约在承担它的声明上完整说明一次。源码注释自包含，可引用可解析的代码符号。源码中禁用指向仓库 `docs/` 文件、章节及对应网页的引用。清理范围内的复述、过期说明和注释掉的旧实现。
- C# XML 注释用与声明同级缩进的 `/// `，放在声明和特性列表之前。每个带正文的块级标签将开始标签、正文和结束标签分别占行。同级标签连续，嵌套块缩进一级。多段用 `<para>`，多行代码用 `<code>`。让 `<see />`、`<paramref />`、`<typeparamref />` 和 `<c>…</c>` 随正文行内书写，`<inheritdoc />` 独立占行，自闭合标签的 `/>` 前留一个空格。
- XML 标签按摘要、泛型参数、参数、返回值或属性值、异常、补充说明、示例排列。参数类标签用于补充签名未表达的语义。使用时按声明顺序覆盖该类所有参数并核对名称。检查 `cref` 指向实际符号。记录调用方可以依赖的异常和触发条件。
- AXAML 注释紧贴对应元素。保留诊断器读取的标记及位置。`<!-- layout -->` 标记符合规则的布局常量，`<!-- shared: reason -->` 说明跨控件共享理由，`<!-- owner: reason -->` 紧邻对应 `ControlTheme` 并解释为何跟随宿主。核实机器读取的注释语义后再改写其文字。

## 修订与复核

1. 按源证据补充缺失或过期的契约，修正排版。核对差异限于注释，保留源码行为及诊断标记含义。复用目标项目适用的 XML、AXAML 或文档检查，记录实际验证范围和结果。
2. 同一文件有暂存与未暂存改动时，保留各自的内容和契约。仅获工作区编辑授权时，在工作区适用的源码上修订，并报告暂存区仍待处理的条目。获授权同步到本次暂存时，按暂存源码编写对应的注释差异并只暂存该差异，保留其他未暂存改动。按最终暂存源码复核，暂存内容变化后重查受影响范围。
3. 报告检查范围和源码版本。每项问题给出文件与行号、缺失或过期的契约、实际依据和处理结果。待核实项写明缺少的证据。用户仅要求检查时交付发现，要求补齐时交付改动和验证结果。

## 示例

用户说「提交前检查注释」。暂存的 `TryLookup` 在找不到键时返回 `false` 并把 `value` 设为 `null`，工作区的另一版返回空字符串。指出暂存注释缺少失败契约，并按暂存实现提出如下注释。此请求为只读，交付发现和建议。

```csharp
/// <summary>
/// Looks up a value by key.
/// </summary>
/// <param name="key">
/// The key to look up in the registry.
/// </param>
/// <param name="value">
/// The matched value when found, or <see langword="null" /> otherwise.
/// </param>
/// <returns>
/// <see langword="true" /> when the key is found, or <see langword="false" /> otherwise.
/// </returns>
```
